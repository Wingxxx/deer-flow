- **统一抽象层**：所有通道均继承自 `app.channels.base.Channel` 基类，遵循 `start`/`stop`/`send` 生命周期契约，并通过 `MessageBus` 进行异步解耦通信。
- **并发模型适配**：针对各平台 SDK 特性采用差异化并发策略。钉钉、飞书、Discord 和 Telegram 使用独立线程运行阻塞式 SDK 客户端（如 `dingtalk-stream`、`lark-oapi`、`discord.py`），通过 `asyncio.run_coroutine_threadsafe` 与主事件_loop_交互；Slack 和 WeCom 采用原生异步 WebSocket 客户端；微信则基于 `httpx` 实现长轮询。
- **流式响应机制**：飞书、钉钉（AI Card）和 WeCom 支持真正的流式更新（Patch/Stream API）；其他平台通过“正在处理”占位符或分块发送模拟流式体验。
- **身份与连接管理**：集成 `connection_identity` 模块，支持通过 OAuth State/Connect Code 将外部 IM 用户绑定至内部 DeerFlow 用户体系，并在消息元数据中注入连接上下文。
