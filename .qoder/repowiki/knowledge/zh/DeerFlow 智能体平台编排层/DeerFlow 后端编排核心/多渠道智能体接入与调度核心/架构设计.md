- **核心编排**：`ChannelService` 作为顶层入口，负责从配置中动态加载并管理各平台通道（如Slack、Feishu）的生命周期，并初始化共享的 `MessageBus` 和 `ChannelStore`。
- **通信解耦**：采用生产者-消费者模式，各平台适配器将接收到的消息封装为 `InboundMessage` 发布至 `MessageBus`，由 `ChannelManager` 统一消费并调用 Gateway API 触发智能体推理。
- **会话映射**：`ChannelStore` 维护外部平台 `chat_id/topic_id` 与内部 LangGraph `thread_id` 的持久化映射，确保多轮对话上下文的一致性。
- **响应路由**：`ChannelManager` 将智能体产生的 `OutboundMessage` 重新发布至总线，各通道通过订阅机制识别归属消息并执行发送，支持基于平台能力的流式（Streaming）与非流式差异化处理。
