- 状态更新采用“先内存后持久化”模式：先在内存中更新 `RunRecord` 状态，随后异步调用 `_persist_status` 进行最佳努力（Best-effort）的持久化，确保持久化失败不阻塞主流程。
- 关键写操作具备原子性保障：在 `create` 和 `create_or_reject` 等方法中，若持久化存储写入失败，会通过 `finally` 块回滚内存中的注册记录，防止出现“幽灵运行”。
- 统一使用 `RunContext` 数据类封装执行依赖：将 `checkpointer`、`store`、`event_store` 等基础设施依赖聚合到 `RunContext` 对象中，避免 `run_agent` 函数签名过度膨胀。
