- **服务拓扑**：以 `nginx` 为统一入口（端口 2026），将 API 请求路由至 `gateway`，静态资源指向 `frontend`。
- **环境隔离**：提供 `docker-compose.yaml`（生产/Prod）与 `docker-compose-dev.yaml`（开发/Dev）两套配置，前者侧重稳定性与多副本控制，后者挂载源码卷以实现热重载。
- **沙箱集成**：`provisioner` 服务作为可选组件，通过挂载宿主机的 Kubeconfig 或 Docker Socket，在 Kubernetes 集群或 DooD (Docker-out-of-Docker) 模式下动态管理代码执行沙箱。
- **网络通信**：所有服务共享 `deer-flow` 桥接网络，并通过 `host.docker.internal` 实现容器与宿主机（如 K8s API Server）的跨边界通信。
