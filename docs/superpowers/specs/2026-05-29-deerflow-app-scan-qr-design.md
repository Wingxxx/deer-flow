# DeerFlow App 扫码绑定服务器地址 - 设计方案

## 概述

在现有 URL 配置功能基础上，新增扫二维码直接绑定服务器地址的功能。用户扫码后自动提取 URL、自动 `/health` 验证、自动保存并加载，实现「一扫即用」的闪电绑定体验。

## 扫码入口

### 入口 1：错误覆盖层
WebView 加载失败时显示的错误页中，增加「📷 扫码自动绑定」按钮，排在第一位（最常用场景）。

```
┌──────────────────────────────┐
│        ⚠️                     │
│    无法连接服务器              │
│  当前网络无法访问指定地址...   │
│                              │
│  ┌─ 当前地址 ──────────────┐ │
│  │ http://192.168.1.56...  │ │
│  └─────────────────────────┘ │
│                              │
│  [📷 扫码自动绑定]            │
│  [✏️ 修改服务器地址]          │
│  [🔄 检查网络并重试]          │
└──────────────────────────────┘
```

### 入口 2：配置浮层
配置面板的「测试连接」按钮下方增加「📷 扫码自动绑定」按钮。

```
┌──────────────────────────────┐
│      服务器设置           ✕   │
│  服务器地址                   │
│  ┌────────────────────────┐  │
│  │ http://...             │  │
│  └────────────────────────┘  │
│  [🔌 测试连接]               │
│  [📷 扫码自动绑定]            │
│  ✅ DeerFlow 服务器已验证 ✓   │
│  [💾 保存并加载]              │
│  [↩️ 恢复默认地址]            │
└──────────────────────────────┘
```

## 核心流程：全自动闪电绑定

```
用户点击「📷 扫码自动绑定」
  ↓
uni.scanCode() 调用系统相机扫码
  ↓ 成功
提取二维码内容 → 格式校验（非空/非空格/非中文/自动补http://）
  ↓ 通过
内网检测提示（公网域名则toast警告，不阻断）
  ↓
自动 /health 验证 GET {url}/health（5秒超时）
  ├─ 成功 + service="deer-flow-gateway" + status="healthy"
  │   → 自动保存到 df_custom_url → 关闭当前面板 → 重新加载 WebView
  │   → toast "扫码绑定成功: {url}"
  └─ 失败/不匹配
      → 显示错误信息 → 不保存 → 停留在当前界面
```

## 代码变更

仅修改一个文件：`pages/index/index.vue`

### 新增方法

| 方法 | 说明 |
|------|------|
| `scanQRCode()` | 调用 `uni.scanCode()` 扫码，成功后调用 `processScannedUrl()` |
| `processScannedUrl(url)` | URL 校验 → 自动补全协议 → 自动 `/health` 验证 → 自动保存 |

### 新增状态

| 变量 | 类型 | 说明 |
|------|------|------|
| `scanning` | Boolean | 扫码进行中标志，防止重复点击 |

### 模板改动

- 错误覆盖层：在现有按钮上方增加「📷 扫码自动绑定」按钮
- 配置浮层：在「测试连接」按钮下方增加「📷 扫码自动绑定」按钮

### 复用逻辑

扫码后的 `/health` 验证完全复用现有 `testConnection()` 中的 `uni.request` 逻辑，通过 `/health` 验证后复用 `saveAndLoad()` 的存储+加载逻辑。

## 开发环境调试

在配置面板中增加隐藏的调试入口：**长按标题「服务器设置」3 秒**，在「测试连接」下方出现 Debug 输入框，可手动输入模拟扫码内容测试流程，确保功能不报错。

## 约束条件

- ❌ 不新增第三方 SDK 或插件
- ❌ 不新增页面（单页面不变）
- ❌ 不修改 manifest.json 的权限配置（已包含 CAMERA）
- ✅ 纯 URL 二维码格式（不支持自定义协议）
- ✅ 扫码后必须通过 `/health` 身份验证才能保存（安全硬限制不变）

## 测试矩阵

| # | 场景 | 预期 |
|---|------|------|
| 1 | 扫描有效 DeerFlow URL | 闪电绑定成功，WebView 加载 |
| 2 | 扫描纯 IP（无协议前缀） | 自动补全 http://，绑定成功 |
| 3 | 扫描公网 URL | /health 验证失败，提示非 DeerFlow 服务器 |
| 4 | 扫描无效内容（纯文本） | 提示「二维码内容无效」 |
| 5 | 扫描含空格/中文的 URL | 提示「二维码内容无效」 |
| 6 | 扫描非 http/https 协议 | 提示「二维码内容无效」 |
| 7 | 用户拒绝相机权限 | toast 提示需要相机权限 |
| 8 | 扫码过程中取消/返回 | 无异常，回到原界面 |
